A GOOD PLACE TO BEGIN

Find your flow.

Get your first request running, bring your existing work along, and make Reqglide your own.

Your workspace starts here.

Reqglide is a local-first API client. Requests, collections, scripts, and environment definitions live in a workspace on your machine. No account or hosted workspace is required.

Your last workspace reopens automatically when you launch Reqglide, together with available saved request-tab recovery and your selected environment. After upgrading from a version before 0.1.2, open your workspace once to remember its location. Closing the app keeps it remembered; choosing Close workspace explicitly clears automatic reopening. If the folder moves or becomes unavailable, use Open to select it again.

The current release is an early Windows x64 preview. The source is MIT licensed and contributions are welcome. The capability ledger tracks implemented features and remaining work.

Install on Windows.

  1. Download the Windows EXE preview, or choose the MSI installer.
  2. Review the release notes and checksums. Preview installers are unsigned; Windows may show a publisher or reputation warning. Check the file source before proceeding.
  3. Run the installer and launch Reqglide.
  4. Select New workspace, give it a name, and choose a parent folder. Reqglide creates a child directory containing workspace.yaml.
Upgrading from the old “API Client” NSIS preview? Uninstall that preview first while preserving application data, then install Reqglide. Existing workspace folders can be opened directly. Packaged upgrade acceptance remains in progress.

You can verify a downloaded installer in PowerShell:

Get-FileHash .\reqglide_0.1.2_windows-x64-setup.exe -Algorithm SHA256

Compare the result with the release checksums. The full release-readiness checklist is available in the repository.

Send your first request.

  1. Choose an HTTP method and enter your endpoint in the URL bar.
  2. Add query parameters and headers in their tabs.
  3. For JSON, select Body → raw → JSON. Make sure the request uses Content-Type: application/json. Token endpoints may instead require x-www-form-urlencoded.
  4. Choose the appropriate authentication in Auth, then select Send.
  5. Inspect the status, response headers, and body. Save the request into a collection or nested folder for next time.

A request is sent only when you choose Send or start a collection run. Importing a request does not execute it.

Bring your work with you.

Paste cURL

Paste a cURL command directly into the request URL bar. Reqglide imports the method, URL, supported headers, authentication, and body so you can review and edit it. You can also use Import cURL from the toolbar.

Import a collection or API definition

Open a workspace, then choose Tools → Import API file. Select a Postman collection/environment or an OpenAPI/Swagger JSON or YAML file. Review any compatibility warnings before saving the import.

Compatibility is growing. Imported authentication, scripts, or protocol details may need review; Reqglide does not claim complete Postman parity.

Environments that keep you in context.

Open Tools → Environments, create an environment such as Stage, add variables, and select that environment in the workspace.

  • Shared: plain text in the workspace file. Suitable for values you intend to share.
  • Secret: stored in the OS credential store. Suitable for tokens and credentials.
  • Local: also stored on this device, with visible values in the environment editor. Useful for machine-specific configuration.

Reference a variable with double braces:

URL:    {{baseUrl}}/v1/projects
Auth:   Bearer Token
Token:  {{access_token}}

In Auth → Bearer Token, enter the raw token or {{access_token}}; Reqglide adds the Bearer prefix. A manually entered Authorization header needs the full value Bearer {{access_token}}.

Save a generated token

For a token response, use Extract variable to save access_token to the active environment. Token-like values default to Secret storage. Or pre-create a Secret variable called access_token and use a post-response script:

const token = pm.response.json().access_token;
pm.environment.set("access_token", token);

New variables created by scripts use Shared storage, so pre-create sensitive variables as Secret. A request that references a missing value is stopped before transport.

Credentials typed directly into request fields, network settings, or Shared variables are saved as plain text in workspace configuration. Use Secret references for sensitive values and review files before committing them to Git.

Keep checks close to your requests.

The Scripts tab contains pre-request and post-response scripts. The current compatibility surface includes pm.test, pm.expect, environment access, and selected request/response helpers.

pm.test("Request succeeded", () => {
  pm.response.to.have.status(200);
});

pm.test("Response has projects", () => {
  pm.expect(pm.response.json()).to.have.property("projects");
});

Scripts run in a resource-limited native JavaScript runtime. Filesystem, process, module-loader, and direct network access are unavailable. See the scripting reference for the exact supported API and limits.

Use Tools → Collection runner for repeated runs, iterations, CSV/JSON data rows, and report exports.

Make your network work for you.

Open Tools → Network and TLS for system, custom, or disabled proxy modes, no-proxy rules, custom CA certificates, and client identities for mTLS.

If an endpoint works in another desktop client but times out here, compare the proxy and VPN route before changing the token. A connection timeout occurs before an HTTP authentication response. Request timeout and response-size controls are available in the request’s Settings tab.

Leave certificate verification enabled for normal use. Custom CA and client identity paths reference local files and may need updating when you move a workspace.

Keep a copy. Share the right details.

Use Tools → Back up workspace for a versioned copy of saved configuration. Restore workspace backup creates a separate workspace identity and rejects an existing destination folder.

Backups are private, unencrypted files. They include Shared values and literal credentials in saved configuration. Secret/Local values, history, cookies, unsaved tabs, upload bytes, and certificate files are excluded. Re-enter device-only values after restoring.

For support, Tools → Export support diagnostics saves app information, counts, and network/TLS configuration flags. It excludes request data, names, URLs, paths, scripts, variable values, and credentials. Nothing is uploaded automatically.

Read the backup and support guide for the exact boundaries.

Build the next part with us.

Reqglide is MIT licensed. You can help with documentation, accessibility, bug fixes, protocol support, and the workflows that matter to your team.

  • Report a bug with a minimal reproduction, app version, and expected behavior.
  • Suggest a feature and explain the workflow it would improve.
  • Read the roadmap and contributor guide before opening a pull request.

Remove tokens, cookies, certificates, and personal identifiers from reports. Follow the repository’s security policy for suspected vulnerabilities.

Build from source.

Install Node.js 24+, pnpm 11.19, stable Rust, and the platform build tools required by Tauri 2. On Windows, that includes the MSVC build tools and WebView2 runtime.

git clone https://github.com/Sid532001/reqglide.git
cd reqglide
pnpm install --frozen-lockfile
pnpm dev

pnpm dev launches the desktop application. To run the landing page locally instead, use:

pnpm site:dev

Open http://127.0.0.1:4173. The landing page is a separate static website; it does not need Tauri or a cloud account. Its built HTML can also be opened directly from apps/site/dist/index.html.

For architecture, verification commands, and platform notes, start with the repository README.
